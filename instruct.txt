一、项目简介
------------------------------------------------------------
一个安卓端"游戏创作 Agent"平台，三个子页面：我的游戏(首页)，创作，设置」页配置
1.“我的游戏(首页)”展示用户已经制作好的游戏，点击即可立即游玩。
2.“创作”页面可以让用户用自然语言描述游戏（如"做一个打地鼠小游戏"），AI 即时生成制作单文件 HTML5 游戏，SSE 流式输出（打字机效果）。
	界面逻辑类似豆包/元宝这类对话Agent，Agent Loop尽量保证验收标准（代码无语法错误可运行）。
	切换页面或对话时允许后台运行，制作好后可在 WebView 里立刻运行游玩。
	若点击运行出错则可让 AI 直接修复，也可继续对话迭代修改（"加连击计分"），修改基于上一版完整代码进行；
	成品游戏可保存到本地游戏库（标题/描述/游玩次数），随时重开、继续编辑、删除。
3.“设置”页面可以选择 LLM 厂商模型，配置 API Key（DeepSeek / Kimi / OpenAI / Claude / 自定义）；

核心思路：游戏不是编译出来的，而是 AI 生成的文本 = 可运行产物（HTML 文件），运行期由 WebView（Chromium 内核）解释执行。
无编译环节，生成即玩；鸿蒙 ArkWeb 同为 Chromium 内核，双端可复用。

五、核心流程
------------------------------------------------------------
1. 首次生成：
   系统提示词 + 模板示例 + 用户指令 → LLM 流式输出 → 抽码（失败自动重试 1 次）
   → 校验警告 → 写入草稿 → 会话落盘 → UI 出现"立即游玩"。
2. 迭代修改：
   <game_code> 包裹上一版完整 HTML + 新指令 → 模型输出完整新版 → 整文件覆盖。
3. 保存：
   草稿 → 建 games/<id>/ 目录 + games.json 索引，清空草稿；编辑已存游戏 →
   更新 index.html + session.json + 标题（不新建条目）。
4. 游玩：
   game 来源读 games/<id>/index.html（游玩次数+1）；draft 来源读 drafts/latest.html。
5. 错误修复：
   WebView JS 报错 → 覆盖层 → "让 AI 修复" → 错误文本进会话发起新一轮生成。
